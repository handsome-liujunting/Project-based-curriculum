# V4 反思

日期：2026-10-06
口径：按课件"好迭代 = 更好的决定，而不是更多改动"，从五个角度回看这一轮。**写进去的都是实际发生的，包括做得不漂亮的地方。**

---

## 1. 哪些改动是"更好的决定"，哪些只是"更多改动"？

**真正有价值的：**
- **迭代历程区块**：把一个只能靠嘴说的过程变成了访客能自己看的东西。四个版本的首屏并排放着，"改了什么、为什么改"写在卡片里 —— 这是这次作业唯一一个"非做不可"的功能。
- **版本号只留一个来源**：以后收集到的意见不会再贴错版本。
- **作品区口径统一**：去掉了"同一个项目当两个作品"的自相矛盾，顺带把真实的数字分身单独列出来。
- **错误文案友善化**：访客不该看到 `Failed to fetch`。

**差点做错的（很重要，所以写在最前面）：**
- 我一度相信"手机端导航和标题被裁掉了"，准备去改 CSS。**先复现**才发现是截图工具的伪影：Windows 上浏览器窗口宽度下不去（要 375 实际渲染 504 再裁成 375），站点本身在真 375 视口下 `overRight=none`、7 项导航全可见。差一点为一个不存在的缺陷动样式。
- 同理，"整页截图里首屏被拉长"也不是站点的毛病，而是 `.hero{min-height:90vh}` 遇到超高视口的必然结果 —— 修的是我的拍摄口径，不是页面。

- **历程区块加版本目录**：我以为「区块里有四张卡」就等于「访客看得到四个版本」。自己在页面上复核一遍才发现，滚到那一节时第一屏只有 V1、V2 —— **存在不等于可见**。加一排版本目录之后，「一共四次改版」在第一眼就能看到。

**刻意没做的：** 迭代图懒加载、换 `supabase-js`、留言板加登录。前两个性价比不足（分别记为"下次加图时的第一步"和"刻意偏离"），第三个和匿名墙的意图冲突。

## 2. 这一轮卡在哪里？

- **最大的坑是"看不到真相"。** 截图工具骗了我两次（裁切、90vh 撑高）。这两次的共同教训是：**先证明测量工具可信，再相信测量结果。** 后来我用 CDP 设备模拟拿真视口、用探针直接读几何数据，才把"看起来坏了"和"真的坏了"分开。
- **第二个坑是编码。** 单文件导出漏内联图片，查到最后不是图片的问题，而是 PowerShell 5.1 把无 BOM 的 `.ps1` 按 ANSI 解析，中文注释吞掉了后面的赋值语句。脚本改成纯 ASCII 并在内联前后做数量校验（不符即中止、不写文件）后才稳定。
- **第三个坑是外部依赖说没就没。** 留言板和反馈表单依赖的 Supabase 项目在提交前几天不可达了（域名解析不到，多半是免费额度闲置被暂停）。当天去控制台恢复并只读复验通过，但教训留下了：**「能演示」和「能用」是两回事**，页面必须有「后端不在时也不难看」的降级路径。

## 3. 我怎么知道它真的更好了？

不是靠"看着顺眼"，而是靠可复跑的检查 + 同口径对比：

| 手段 | 结果 |
| --- | --- |
| `verify_v35.ps1 -SiteOnly` | FAIL count = 0（10 组结构/契约/安全检查） |
| `sync_site.ps1` 同步发布根 | 4 项拷完、无残留、自动校验 FAIL count = 0、20 个文件 |
| `export_single_file.ps1` | 4/4 图片内联为 data URI，离线无断图 |
| 桌面 1440×900 与手机 375×812 探针 | 两套视口都无横向溢出；区块坐标与预期一致 |
| Before/After 同口径整页图 | `v35-full-before.png` 与 `v4-full.png` 可比 |

同时我**写清楚了没验到的部分**：真机没走过完整提交路径、弱网性能没测、后端恢复后的真实提交这轮没做（只做只读复验，因为约定过不再往公开墙上写测试数据）。

## 4. 如果还有时间，下一轮做什么？

1. 收到真实反馈后按 `docs\V4-反馈决策表.md` 的流程逐条处理（先复现、再判定、四种决定选一个）。
2. 后端恢复后补一次真实提交复验，并给两个表单加"离线/失败重试"的引导。
3. 迭代缩略图加懒加载；把"当前版本"的标记改成从 `siteVersion` 自动读，避免图过期。
4. 把作品区那几个"待补充"补上。
5. 真机上把留言和反馈各走一遍。

## 5. 反馈有没有改变我原来的想法？

- **外部反馈很少：同伴口述 1 条、公开留言板 4 条真实留言（都是"有人来过"式的祝语），表单则连我自己都读不到**（RLS 只给 `INSERT`，查询返回 `401 / 42501`）。我没有拿自测冒充访客反馈，决策表里每条都标了真实来源 —— 这本身是个待补的缺口，我把它写在明面上。那条唯一的同伴意见（进度条偏小）我量了、记了，也**明确写了为什么不改**，而不是含糊带过。
- 但这轮**确实被"复现"改变过一次想法**：我本来认定手机端有毛病，复现之后改成"是我的验收方法有毛病"。这是这次最值钱的一条经验：**先复现，再动手；验证优先于修改。**
- 而"先复现"这一条，本轮又救了一次：我一度以为历程区块只显示了 V1、V2（也就是 V3/V4 没上去）。回到页面上用探针读 DOM 才发现四张卡都在，只是排在第二行、落在首屏之外 —— **又一次"看起来坏了"**。加版本目录时也一样，改完先点一次、量一次落点，才敢说"这次真的看得见了"。
