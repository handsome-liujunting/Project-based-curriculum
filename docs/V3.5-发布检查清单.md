## 1. 发布前：本地校验（每次必做）

```powershell
# ① 结构 / 资源引用 / id 唯一 / 标签配对 / 脚本顺序 / 外链 / 编码 / 密钥 八项检查
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\verify_v35.ps1" -Root "outputs\personal-homepage-v35"
```

**通过标准：`FAIL count = 0`**，且第 8 节显示 `ok no key material / service_role in config code`。

逐项含义：

| 检查项 | 期望 | 为什么 |
|---|---|---|
| 1 引用的本地文件是否存在 | 全部 `ok` | 少一个文件页面就缺一块 |
| 2 样式/脚本是否都被引用 | 三个 js + 两个 css 都 `referenced=True` | 防止写了却没接上 |
| 3 id 唯一性 | `no duplicates` | 重复 id 会让 JS 取错元素 |
| 4 标签配对 | 全 `ok` | 未闭合标签会让后面整段结构走形 |
| 5 脚本顺序 | `ok config loaded before feedback` | `feedback.js` 依赖 `feedback-config.js` 先执行 |
| 6 外部链接扫描 | `no external url` | 版权合规 + 断网可用 |
| 7 编码 / BOM | 全部 `bom=False` | BOM 会在部分环境产生多余空白 |
| 8 密钥泄漏 | `ok` | 红线，见接入说明第 8 节 |

## 2. 改文案后的固定动作（最容易忘的一步）

V3.5 的字体是**子集化**的：只包含页面实际用到的那些字。
所以**只要新增了汉字，就必须重新生成字体子集**，否则新字会以系统字体显示，和其他字不一致。

```powershell
# 重新生成两个字体子集（会联网访问 Google Fonts，需要网络）
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\resubset.ps1" -Root "outputs\personal-homepage-v35" -ExtraFile "tools\extra_display.txt"
```

固定四步，一步都别跳：

1. 改 `index.html`（或 JS 里用展示字体渲染的文案）
2. 重跑字体子集（上一段）
3. 重跑 `verify_v35.ps1` 确认 `FAIL count = 0`
4. 重跑单文件导出（第 1 节 ③），然后 `git commit`

**参考值**（用于快速判断子集是否真的重建了）：

| 版本节点 | 汉字数 | zcool-kuaile-subset.woff2 |
|---|---|---|
| V3.5 初版 | 284 | 29 464 B |
| 第二格改文案后 | 288 | 29 952 B |
| 台词 +3 条后 | 300 | 31 272 B |
| 删掉前三条台词后（当前） | 293 | 30 452 B |

> 若汉字数与上表当前值（293）一致、但字节数也完全一致，说明文案没变，不用重建。

## 4. 站点源码同步到仓库根目录

**目标结构**（GitHub Pages 只能从仓库根或 `docs/` 发布，所以站点源码要放到根目录）：

```
/                      ← 仓库根 = 发布根
├── index.html         ← 由 outputs/personal-homepage-v35/index.html 复制
├── css/               ← style.css、feedback.css
├── js/                ← main.js、feedback-config.js、feedback.js
├── assets/fonts/      ← 两个 woff2 + 两份 OFL 授权全文 + README
├── outputs/           ← 历史版本（V1 / V2 / V3 / V3.5 源码与截图），不参与发布
├── docs/              ← 制作文档
└── tools/             ← 导出脚本
```

**为什么站点源码放根、历史版本留 `outputs/`**：Pages 只认根目录（或 `docs/`），
放根目录后访问 `https://handsome-liujunting.github.io/Project-based-curriculum/` 直接就是主页；
历史版本留在 `outputs/` 里作为过程证据，但不会被当作首页。

**一条命令完成同步 + 校验**（推荐，脚本幂等，可反复跑）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\sync_site.ps1" -Src "outputs\personal-homepage-v35" -Dst "."
```

脚本只做四件事：复制 `index.html`、`css\`、`js\`、`assets\`（**只覆盖同名文件，不删除任何东西**）、
列出发布区文件清单、报告 stale 文件（源里没有但目标里有的，只警告不删）、最后自动调用校验脚本。

**手工校验命令**：

```powershell
# 最小校验（源码目录）
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\verify_v35.ps1" -Root "outputs\personal-homepage-v35"

# 根目录再走一遍（必须加 -SiteOnly，否则会连 uploads\、outputs\ 一起扫描）
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\verify_v35.ps1" -Root "." -SiteOnly
```

`-SiteOnly` 只扫描 `index.html` + `css\` + `js\` + `assets\`，输出从上千行降到十几行，
`FAIL count = 0` 的判定标准不变。

> 注意：根目录版与 `outputs/personal-homepage-v35/` 的**相对路径一致**（都是 `css/`、`js/`、`assets/`），
> 所以复制过去不需要改任何一行路径。这一点在 V3.5 建站时就按此约定设计。
>
> 校验方式：`Get-FileHash` 对比 11 个发布文件，全部 `SAME` 才算同步成功。

## 5. 发布到 GitHub Pages

1. 把仓库推到 GitHub（仓库名：`Project-based-curriculum`，public）。
2. 仓库 **Settings** → **Pages**：
   - `Source` = **Deploy from a branch**
   - `Branch` = `main`，`Folder` = **/ (root)**
   - Save
3. 等 1–2 分钟，访问 `https://handsome-liujunting.github.io/Project-based-curriculum/`。
4. **强制刷新**（`Ctrl+F5`）确认看到的是新版本 —— 浏览器与 Pages 都有缓存。

> 如果用了自定义域名或 `docs/` 目录，回头更新本节与首页链接。
> 首次发布失败最常见的原因：仓库是 private（免费账号不支持 Pages）、
> 或分支不是 `main`、或文件不在选定目录下。

## 7. 回归与回滚

- **回归**：本清单第 1、2、3 节就是完整的回归流程；每次改完都跑一遍，
  哪怕只改了一个字（字体子集那步最容易忘）。
- **回滚**：V3.5 之前的可用版本是 `outputs/personal-homepage-v3/`（V3 基线，已冻结未改）。
  若 V3.5 上线出问题，把它复制到根目录再发布一次即可回到 V3；
  代码层面也可 `git revert <commit>`（历史提交见 `docs/V3.5-制作流程与记录.md`）。
- **反馈数据**：反馈存在 Supabase，不随站点回滚丢失。

## 8. 已知问题与说明

| 问题 | 说明 | 处理 |
|---|---|---|
| DeepWorks 内置浏览器打不开本页（白屏） | 对比测试：极简静态页可显示，本页在 `file://` / `http`、分文件 / 单文件、有 JS / 无 JS 四种组合下均白屏；同一文件用 Edge 无头渲染正常（276 KB 彩图）。判定为**该内置浏览器渲染本页的能力限制**，与页面代码无关 | 用系统浏览器打开，或在产物面板预览；代码侧已加"淡入兜底"，对真实浏览器无副作用 |
| 单文件版是快照 | 改源码后不同步 | 每次改完重跑导出（第 1 节 ③） |
| 新增汉字要重建子集 | 子集是静态的 | 见第 2 节四步 |
| 本地常驻服务不稳定 | 该环境下进程会被清理 | 用单文件版预览，或需要时重新起服务 |
