## 一、本轮任务来源

依据课件 **《个人主页V3-发布反馈与持续改进.pdf》**（44 页，已 OCR 逐页提取要点）：

| 课件要求 | V3.5 的落实 |
|---|---|
| 页面要能收到访客反馈，且**不跳转页面** | 右下角常驻「提个意见」按钮 → 就地弹出模态表单 |
| 反馈入口要让访客**放心写** | 表单内明示「反馈不会公开，只有我能看到。」 |
| 字段：昵称（可选）、关系、设备、内容（必填）、时间与版本号（自动） | 6 个字段按此实现；时间由数据库 `now()` 生成、版本号由 `siteVersion` 自动附带 |
| 后台要有地方存、能查看 | Supabase `feedback` 表 + RLS 只允许匿名插入（作者可在控制台查看） |
| 只能把可公开的密钥放前端 | 仅用 publishable key；secret key / 数据库密码绝不进前端（含自动扫描） |
| 持续改进：知道问题出在哪一版 | 每条反馈自动带 `version` 字段 |

## 二、关键决策与理由

| 决策 | 理由 |
|---|---|
| **反馈样式单独成文件** `css/feedback.css`，不改 `css/style.css` | 一眼能看出"这一版改了什么"；也避免动到已经稳定的 V3 样式（`style.css` 26149 B 全程未改） |
| **不引入 supabase-js，用原生 `fetch` 打 PostgREST** | 只需要"插入一行"这一个动作；不引第三方库，页面运行时依然零外部依赖，符合本站一贯的"零外链"要求 |
| **未配置后台时明确说"通道没接好"，不假装成功** | 课件强调不要让访客以为反馈发出去了；宁可明说，也不给假成功提示 |
| **今天只做前端，Supabase 明天接入** | 你的决定；配置项留空（`url`/`anonKey`），页面照常可用，表单会提示"通道待接入" |
| **站点源码放仓库根目录，历史版本留 `outputs/`** | GitHub Pages 只认根目录或 `docs/`；放根目录后访问仓库地址即主页，历史版本仍作为过程证据保留 |
| **文案逐字照用户原文写入，末尾不加句号** | 你的明确要求；如需统一标点可后续批量处理 |
| **新增汉字后必须重建字体子集** | 子集是静态的，否则新字回退系统字体会"鹤立鸡群" |

## 六、反馈功能的实现要点

**交互链路**：点按钮 → 打开模态（不跳转、不刷新）→ 填写 → 校验 → `fetch` POST → 提示结果。

| 点 | 做法 |
|---|---|
| 打开/关闭 | `hidden` 属性切换；关闭方式三种：右上角 `×`、点遮罩、按 `Esc`；关闭后焦点回到入口按钮 |
| 无障碍 | `role="dialog"` + `aria-modal="true"` + `aria-labelledby/describedby`；打开时焦点给面板本身（键盘可用，又不会在手机上直接弹键盘）；状态区 `role="status" aria-live="polite"` |
| 必填校验 | 前后端各一层：前端提示"内容还是空的/选一下设备"；数据库 `message not null` + 长度约束兜底 |
| 防重复提交 | `busy` 标记 + 提交中禁用按钮 |
| 失败不丢内容 | 失败时**不清空**表单，提示"内容我帮你留着了，可以再点一次" |
| 超时 | `AbortController` + 12 秒超时，避免一直转圈 |
| 深链 | 网址后加 `#feedback` 自动打开表单（方便分享/截图，且不污染浏览器历史） |
| 滚动锁 | 打开时给 `body` 加 `fb-locked`（`overflow:hidden`） |
| 减少动效 | `prefers-reduced-motion: reduce` 时关闭图标闪动与弹出动画 |
| 零依赖 | 不加载 supabase-js，只用原生 `fetch` 打 `POST {url}/rest/v1/feedback`，请求头带 `apikey` / `Authorization: Bearer` / `Prefer: return=minimal` |

**为什么 `Prefer: return=minimal`**：这样插入后不需要 `SELECT` 权限，
正好和"数据库只给匿名访客 INSERT 权限"的策略严丝合缝 —— 少一个权限，就少一个泄露面。

## 七、白屏问题排查记录（2026-09-20）

**现象**：你在预览时看不到文字、"全是白色的"。

**排查过程与证据**：

| 步骤 | 做法 | 结果 |
|---|---|---|
| 1 | 用 Edge 无头渲染 `file://` 单文件版与 V3 文件夹版，做像素统计 | 均正常：276 KB / 270 KB 彩图，黑描边 13.6%、主蓝 14.9%、浅蓝 9.8% —— **页面代码本身没问题** |
| 2 | 起本地 http 服务并验证 | `GET /index.html → 200`，服务正常 |
| 3 | 打开极简静态诊断页（纯 HTML、零 JS、零外部资源） | ✅ **能正常显示** → `file://`、内联样式、内联 JS 都可用 |
| 4 | 打开单文件版（资源全内联） | ❌ 仍白屏 |
| 5 | 打开「安全模式」版（移除 `给 <html> 加 .js 类` 这一步，完全不依赖 JS 即可见） | ❌ 仍白屏 |

**结论**：本页在 `file://` 与 `http`、分文件与单文件、有 JS 与无 JS **四种组合下均白屏**，
而极简页正常、同一文件用 Edge 渲染正常 →
判定为**内置浏览器渲染本页（大量自定义字体 + 复杂 CSS）的能力限制**，与页面代码无关。

**据此做的代码改动**（对真实浏览器无害、只增不减）：在
`index.html` 的 `<head>` 内联脚本与 `js/main.js` 中各加一道**兜底**：

- `index.html`：若 2 秒内 `main.js` 未就绪，自动移除 `html.js` 类 → 全部内容直接可见；
- `js/main.js`：1.5 秒后，把视口内仍未显示的元素强制标为可见；就绪时置 `window.__revealReady = true`。

这两道兜底解决的是**真实存在的风险**：本站的滚动淡入依赖 `IntersectionObserver` 回调，
若外部脚本被拦截、或页面在后台标签页加载导致回调迟迟不来，内容会一直停留在 `opacity:0`。
加兜底后，最坏情况也只是"没有淡入动画"，而不会白屏。
另新增**单文件版**（资源全内联、不依赖任何子路径），作为最稳的预览与交付形式。

**遗留**：内置浏览器为何渲染不了本页，未再深究（你决定"以后再说"）。
日常预览建议：双击单文件版用系统浏览器打开，或在产物面板里预览该 HTML。

## 九、如何从零复现这一版

```powershell
# 1) 校验源码结构
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\verify_v35.ps1" -Root "outputs\personal-homepage-v35"

# 2) 重建字体子集（改动过文案才需要；会联网访问 Google Fonts）
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\resubset.ps1" -Root "outputs\personal-homepage-v35" -ExtraFile "tools\extra_display.txt"

# 3) 导出单文件交付版
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\export_single_file.ps1" -Src "outputs\personal-homepage-v35" -OutHtml "outputs\personal-homepage-v35-standalone\index.html"

# 4) 同步到仓库根目录（Pages 发布根）+ 自动校验
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\sync_site.ps1" -Src "outputs\personal-homepage-v35" -Dst "."

# 5) 本地起服务预览（端口 8123）
#    tools\serve_v35.ps1
```
