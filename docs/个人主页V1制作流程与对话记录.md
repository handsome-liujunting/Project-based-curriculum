## 二、课件要求摘要（V1 阶段）

课件主题：**用 Vibe Coding 做出一个真实产品 —— 个人主页 V1→V4 版本迭代**。

V1 = "第一个能看的版本"，目标是用**纯静态 HTML / CSS / JS** 做出一个**能看懂、能预览**的个人主页 MVP。

### 核心主题（课件第2页）
- 核心问题：如何把网页从「能看」一步步做成「可发布、可反馈、可持续改进的真实产品」。
- 主线：个人主页 V1 → V2 → V3 → V4，多轮版本迭代。
- 每个阶段包含：**要做什么（成果）/ 为什么（目的）/ 知识点**。
- 评分原则：看主页能否完成、过程能否可回溯、最终版本能否可用。

### 四项执行心法（课件第4页）
1. 先做出来，再逐步改 —— 先做能看的 MVP，再谈完美。
2. 一次改一类问题 —— 避免一次性大改后无法判断问题原因。
3. 发布后认真听取反馈 —— 让真实访问者参与改进。
4. 每次提交都能解释自己的决定 —— 过程证据与版本说明。

### 技术基线（课件第5页）
- 技术栈：纯静态 HTML / CSS / JS，零构建依赖，可本地预览、可直接发布。
- 版本控制：Git 做 checkpoint 快照，保存 V1→V4 关键节点。
- 发布：静态托管，如 GitHub Pages（资源用相对路径）。

### 页面通用结构建议（课件第8页）
1. Header 顶部导航：品牌 + 菜单 + 主行动按钮。
2. Hero 首屏：姓名 + 一句话介绍 + 标语 + 一两个主行动按钮。
3. 关于我：卡片说明身份、方向、记忆点、所在城市。
4. 项目与作品：代表性作品，简介 + 链接。
5. 兴趣 / 技能（可选）。
6. 数字分身 / 对话入口原型：先做静态占位，后续接真实能力。
7. 联系我：真实可用的联系方式 + 一个明确行动暗示。
8. Footer 页脚：版权声明。

### V1 验收标准（课件第17页）
- 可预览：本地能打开，**桌面 + 手机**两个尺寸都验证（响应式 / 移动优先）。
- 内容真实：简介、经历、项目可核验，**不虚构**。
- 结构清楚：访问者能快速知道「你是谁、做过什么、下一步可以做什么」。
- 第一版记录：Git 保存 V1，并记录下一轮迭代改进重点。
- 关键决策：头像缺照片时用**字母头像占位**（不虚构）；对话能力先做静态原型。

## 四、制作流程（实际操作步骤）

1. **解析 PDF 课件**
   - 读取 `个人主页V1课件.pdf`（模型不支持直接读 PDF，采用解压文本流 + 构建 ToUnicode CMap 的方式提取中文正文）。
2. **梳理 V1 要求** → 见上文"课件要求摘要"。
3. **确认信息与交付偏好** → 通过结构化提问，确认"真实信息 + 双形式记录"。
4. **建立产物目录**
   - `outputs/personal-homepage/`（主页）、`outputs/record/`（记录页）、`docs/`（记录文档）。
5. **编写主页文件**
   - `index.html`：Header / Hero / 关于我 / 项目与作品 / 技能兴趣 / 数字分身原型 / 联系我 / Footer。
   - `css/style.css`：移动优先 + 响应式；统一设计变量、btn--primary/btn--ghost、chip、card-grid（BEM 风格类名）。
   - `js/main.js`：移动端汉堡菜单（is-open 类切换）+ 数字分身占位交互。
6. **本地预览验证** → 用 DeepWorks 浏览器打开 `file://` 页面（openedIn: internal），已可实时预览。
