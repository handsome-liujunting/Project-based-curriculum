## 一、分工

| 我负责 | AI 负责 |
| --- | --- |
| 定这次迭代要做什么、什么不做 | 把决定落成可运行的代码与脚本 |
| 定"什么算做完"（验收口径） | 写探针、量数据、跑校验、出截图 |

## 二、典型对话片段

**1) 我要的是"把改版过程放上首页"**
- 我的要求：首页加一个 V1→V4 的迭代区块，带导航入口和四张版本缩略图；不接受"改了个页面"这种空话。
- AI 产出：`index.html` 的新区块片段 + `css/iterations.css` + 生成缩略图的脚本；采用"先备份、再片段替换、替换前后各做一次 count 校验"的方式改文件。
- 我的判断：**接受**，但要求改完必须跑 `verify_v35.ps1` 且 FAIL count = 0 才算完。

**2) 手机端"导航被裁"**
- 我的要求：手机端截图里导航最后两项和标题像被裁掉了，帮我修。
- AI 起初倾向：直接给 CSS 加媒体查询。
- 我的判断：**否决"直接改"**，要求先复现、拿真实数据。
- 结果：AI 写了几何探针 + CDP 设备模拟工具，实测 375×812 下 `docScrollW=375`、`overRight=none`、7 项导航全部可见；真因是 Windows 上浏览器窗口宽度下不去（要 375 实际渲染 504 再裁成 375）→ **不改站点，改我的验收方法**。这是这次最值钱的一次纠正。

**3) 单文件版"导出后断图"**
- 我的要求：离线单文件交付物里，图片必须内联，不能有断图。
- AI 产出：排查到根因不是图片，而是 PowerShell 5.1 把无 BOM 的 `.ps1` 按 ANSI 解析，中文注释吞掉了后面的赋值语句；脚本改为纯 ASCII，并在内联前后做数量校验（不符即中止、不写文件）。
- 我的判断：**接受**，并以 `images ok 4/4 as data URI` 作为通过标准。

**4) 版本号与字体子集**
- 我的要求：别让以后收集到的意见贴错版本；改了文案不能掉字形。
- AI 产出：指出版本号应只留一个来源（`feedback-config.js` 的 `siteVersion`）；用 `tools\resubset.ps1` 重新生成汉字子集（430 → 432 字）。
- 我的判断：**接受**，并要求把版本号写进回归清单。

**5) "后端连不上"**
- 我的要求：留言板/反馈表单到底还能不能用，别猜。
- AI 产出：先用页内 `fetch` 区分"CORS 问题"和"根本连不上"（连 `no-cors` 都失败 → 不是 CORS），再查 DNS 得到该主机名已解析不到；随后把"把英文 `Failed to fetch` 原样显示给访客"这个问题修掉（中文友好提示 + 原始信息只留 console）。
- 我的判断：**部分接受** —— 站点侧降级立即改；**项目本身不由 AI 结论代替我的操作**，我自己去控制台确认/恢复。

**6) 一处 AI 自身的错误（我要求它修）**
- 现象：跑"慢速探针"（页内等 3 秒的 fetch）时 CDP 客户端崩了。
- AI 产出：定位到是自己的接收循环在同一个 WebSocket 上发起了重叠的 `ReceiveAsync`（快请求掩盖了这个 bug），改成始终只保留一个未完成的接收。
- 我的判断：**接受**，并要求重跑探针验证修复。

## 三、我接受 / 否决 / 延后了什么

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 迭代历程区块 + 缩略图 | 接受 | 这次迭代的核心，访客能自己看到过程 |
| 用真视口/CDP 复测手机端 | 接受 | 推翻了一个假缺陷，避免无意义改样式 |
| 作品区卡片口径统一 | 接受 | 与新街区冲突且过时（高影响 × 低成本） |
| 错误文案友善化 | 接受 | 访客不该看到英文原始报错 |
| 版本号单一来源 / 字体子集重生成 | 接受 | 数据正确性与呈现完整性 |
| 直接把 CSS 改成"修手机端" | **否决** | 缺陷不存在，先复现再动手 |
| 换 `supabase-js` | **否决** | 只需写一条读一列，原生 `fetch` 足够，刻意偏离 |
| 迭代图懒加载 | **延后** | 收益有限，却要同时动导出/同步/截图三条链路 |
| 把自测发现写成"访客反馈" | **否决** | 不实；如实标注来源，缺口写在明面上 |
