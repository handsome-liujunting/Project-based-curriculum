# Supabase 从零开始：建项目 → 建表 → 拿密钥（照着点就行）

这份文件是给「还没建项目」的情况准备的。全程只需要你在浏览器里点几下，遇到任何一步不对，
把**屏幕上的原文/报错**复制给我，我立刻接着处理。

> 一句话记住红线：**数据库密码只存你自己电脑上，任何时候都不要发给我**（发我也不会要）。
> 我需要你发我的只有两样：`Project URL` 和 `publishable key` —— 这两个本来就是公开信息。

---

## 第 0 步：登录 Supabase

1. 打开 <https://supabase.com/dashboard>
2. 点右上角 `Sign in`（或首页的 `Start your project`）
3. 推荐直接用 **Continue with GitHub** 登录（你已有 GitHub 账号 `handsome-liujunting`，最省事，不用记新密码）
   - 如果弹出 GitHub 授权页，点 `Authorize supabase` 即可
4. 登录后如果让你创建 Organization：名字随便填（例如 `liu-junting`），定价选 **Free** 就行

---

## 第 1 步：新建项目

1. 点 `New project`（绿色按钮）
2. 表单这样填：

| 字段 | 填什么 |
| --- | --- |
| Organization | 用默认那个（`liu-junting` 之类） |
| Project name | `liu-junting-homepage`（随便取，只是显示用） |
| Database Password | 点右边的 `Generate a password` 自动生成，然后**立刻复制到你自己电脑的记事本里存好** |
| Region | 选 `Southeast Asia (Singapore)`；没有新加坡就选 `Northeast Asia (Tokyo)` —— 离深圳最近 |
| Pricing Plan | `Free`（免费档足够） |

3. 点 `Create new project`
4. 等 1~2 分钟，界面会从 `Setting up project...` 变成项目主页（能看到一张表结构图 = 好了）

**关于数据库密码**：它只在你直接连数据库（比如用 pgAdmin、psql）时才用得到。
我们前端走的是 HTTP 接口 + publishable key，**用不到数据库密码**。
所以密码丢了也不用慌：Project Settings 里可以 `Reset database password`，不影响我们的接线。

---

## 第 2 步：跑第 1 个 SQL 文件（只建表）

1. 左侧竖排菜单里找到 `SQL Editor`（图标像一张纸带铅笔），点进去
2. 点 `New query`（新建查询），出现一个空的编辑框
3. 打开 `outputs\V3.5-建表-第1步-只建表.sql`，**全选复制**，粘贴进编辑框
4. 点右下角 `Run`（或按 `Ctrl + Enter`）
5. 正常的话，下方 `Results` 面板会显示：`Success. No rows returned`

两种不对的情况：
- 出现红色报错 → 把**报错全文**复制给我（含 `ERROR:` 那几行）
- 如果你发现你操作的界面**不是** `supabase.com` 的控制台（比如是别的网站或本地工具），
  告诉我那个工具的名字 —— 我们这套表和权限是为 Supabase 写的。

---

## 第 3 步：跑第 2 个 SQL 文件（开权限）

1. 还是 `SQL Editor` → `New query`
2. 打开 `outputs\V3.5-建表-第2步-权限与索引.sql`，全选复制，粘贴进去
3. 点 `Run`，同样期望 `Success. No rows returned`

这步给两张表开了 RLS 策略：
- `feedback`（反馈）：只允许插入 → 别人读不到你的反馈
- `messages`（留言板）：允许读 + 插入，不允许改/删

**快捷自检**（不用 SQL）：左侧点 `Table Editor`，应该能看到两张表 `feedback` 和 `messages`。
点进 `messages`，能看到 `id / name / message / created_at` 四个字段就对了。

如果第 2 步报 `role "anon" does not exist`，说明当前不是 Supabase 环境，把截图/报错发我。

---

## 第 4 步：拿两样东西发我

1. 左侧菜单最下面点 `Project Settings`（齿轮图标）
2. 在设置页里找 `API` 或 `Data API`（新版界面叫 `API Keys`）
3. 复制这两个值：

| 要复制的 | 长什么样 | 在页面上的名字 |
| --- | --- | --- |
| Project URL | `https://xxxxxxxx.supabase.co` | `Project URL` |
| publishable key | `sb_publishable_...` | `publishable key`（旧界面叫 `anon public` / `anon key`，形如 `eyJ...`） |

4. 把这两个值发我（直接贴在消息里就行）

**这两个值可以公开**：它们会写在网页源码里，任何人按 F12 都能看到，这是 Supabase 的既定设计。
真正不能外传的是页面下方的 `secret key`（旧称 `service_role`）—— 它绕过所有权限校验，
**绝对不要复制、不要发我、更不要写进网页**。

## 常见坑（遇到先看一眼）

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `0A000: cannot use column reference in DEFAULT expression` | `default now` 少了括号 | 用我给的 SQL 文件，别手抄；正确写法 `default now()` |
| `role "anon" does not exist` | 不在 Supabase 里跑 | 确认地址是 `supabase.com` 的控制台 |
| `relation "feedback" already exists` | 表建过了 | 不用管，脚本里是 `create table if not exists`，直接跑第 2 步 |
| 找不到 `SQL Editor` | 项目还在 Provisioning 中 | 等 1~2 分钟刷新页面 |
| API 页面看到 `service_role` / `secret` | 那是高权限密钥 | 不要复制、不要发我 |
